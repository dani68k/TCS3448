Proyecto:
Aplicación web BLE para control y lectura del sensor TCS3448 sobre ESP32.

Entorno:
- ESP32
- PlatformIO
- Arduino framework
- VSCode
- Web Bluetooth
- TCS3448Manager implementado
- BLE Web funcional
- Dark mode ya aplicado
- Vista Measurement y vista Setup separadas visualmente
- Adquisición RAW del TCS3448 funcionando
- Los canales se reciben correctamente desde el ESP32

IMPORTANTE:
NO debe aparecer ninguna referencia a "ATLANTES" en:
- código
- comentarios
- documentación
- UI
- nombres de clases
- nombres de variables
- nombres de módulos
- textos visibles

==================================================
HITO 5A.1 — HISTOGRAMA RAW
==================================================

OBJETIVO

Añadir a la vista Measurement un histograma espectral RAW del TCS3448.

Este hito se limita exclusivamente a:
- representación gráfica de los canales espectrales
- usando valores RAW ADC
- sin calibración
- sin normalización
- sin ADC %
- sin transmitancia
- sin absorbancia
- sin CSV
- sin almacenamiento
- sin data logging
- sin análisis temporal

El objetivo es dejar muy pulida la visualización RAW.

==================================================
1. PRINCIPIO GENERAL
==================================================

La gráfica debe representar únicamente los canales espectrales principales del TCS3448:

F1
F2
FZ
F3
F4
F5
FY
FXL
F6
F7
F8
NIR

Ordenados por longitud de onda creciente.

Usar estas longitudes de onda centrales:

F1   407 nm

FZ   450 nm
F3   473 nm
F4   516 nm
F5   546 nm
FY   560 nm
FXL  596 nm
F6   636 nm
F7   687 nm
F8   748 nm
NIR  855 nm

NO incluir VIS TL ni VIS BR dentro del histograma espectral principal.

VIS TL / VIS BR deben mostrarse aparte.

==================================================
2. UBICACIÓN EN LA UI
==================================================

En la vista Measurement:

- mantener el header actual
- mantener Device / Connection / Start / Stop
- mantener estado general
- sustituir o complementar la actual lista textual de canales con una card principal:

SPECTRAL MEASUREMENT

Dentro:

- valores actualizados en tiempo real
- leyenda/labels limpios
- tooltip interactivo

Debajo:

- VIS TL / VIS BR
- opcionalmente Advanced Debug colapsable

==================================================
3. TECNOLOGÍA DE GRÁFICA
==================================================

Preferencia:
usar SVG propio + JavaScript.

NO añadir Chart.js, Plotly, D3 u otra librería externa salvo que ya exista en el proyecto.

Motivos:
- 12 barras únicamente
- control completo
- poco peso
- fácil integración
- fácil uso en entorno embebido
- mejor control visual

Crear un componente o módulo específico para la gráfica.

Ejemplo conceptual:

SpectralChart.js

Responsabilidades:
- inicializar
- actualizar datos
- escalar
- dibujar barras
- dibujar ejes
- dibujar labels
- mostrar tooltip
- responder a resize
- seleccionar barra si aplica

No mezclar código BLE con código de render.

==================================================
4. DATOS DE ENTRADA
==================================================

El histograma debe alimentarse desde la estructura de muestra ya recibida por BLE.

No crear un segundo flujo de datos.

  { key: "fz",  label: "FZ",  wavelength: 450 },
  ...
]

No repetir hardcoded mapping en varios lugares.

==================================================

Cada barra debe mostrar:

F1

407 nm

Ejemplo:

407

424

FZ
450

...

NIR
855

No intentar posicionar físicamente las barras con separación proporcional exacta a la longitud de onda en este hito.

Usar barras equidistantes.

El objetivo es:
claridad y lectura.

==================================================
6. EJE Y
==================================================

El eje Y representa:

RAW ADC COUNTS

Título:

Counts

o:

ADC Counts

Escala dinámica.

Ejemplo:

si máximo actual = 1053

usar eje hasta algo razonable como:

0
250
500
750
1000
1250

No usar exactamente el máximo como tope.

Añadir margen visual.

Implementar una función para calcular un "nice max".

Ejemplo:
- buscar máximo actual
- añadir 10-20%
- redondear a valor legible

Ejemplos:
1053 -> 1200 o 1250
17998 -> 20000
32800 -> 35000 o 40000

No usar escala logarítmica.

==================================================
7. COMPORTAMIENTO DEL EJE Y EN TIEMPO REAL
==================================================

Evitar que el eje Y cambie continuamente en cada muestra de forma molesta.

Implementar histéresis o retardo.

Opciones válidas:

- subir inmediatamente si el nuevo máximo excede el rango
- bajar solo si durante N muestras el nivel queda claramente por debajo

Ejemplo conceptual:

increase:
instant

decrease:
after 20 stable samples

o equivalente.

La gráfica debe ser visualmente estable.

==================================================
8. BARRAS
==================================================

12 barras.

Aspecto:
- ancho consistente
- esquinas ligeramente redondeadas
- separación uniforme
- animación suave opcional
- transición de altura 100-200 ms

No usar animaciones pesadas.

Mantener 60 fps razonables.

15. ESTADO DESCONECTADO
==================================================

pero mostrar:

No borrar necesariamente la gráfica.

Opcional:
reducir opacidad o marcar "Last sample".

No simular datos.

==================================================
16. ESTADO STOPPED
==================================================

Si la adquisición se detiene:

mantener última muestra.

Mostrar:

IDLE

o:

STOPPED

La gráfica no debe desaparecer.

==================================================
17. SATURACIÓN
==================================================

Si la muestra recibida indica saturación:

- mostrar estado SATURATED
- usar rojo en badge/status

NO modificar los valores RAW.

NO recortar barras manualmente.

La gráfica debe mostrar los counts recibidos.

Si existe analog saturation o digital saturation diferenciada:
mostrarlo en Advanced Debug o en tooltip de status.

==================================================

12 barras con labels completos.

reducir font-size y separación.

No ocultar canales.

Usar ResizeObserver si conviene.

==================================================
20. PERFORMANCE
==================================================

Las muestras pueden llegar periódicamente.

Evitar:
- recrear todo el DOM en cada actualización
- crear un SVG nuevo en cada muestra
- memory leaks
- listeners repetidos

Inicializar una vez.

Después:
actualizar atributos:
- height
- y
- text
- tooltip data
