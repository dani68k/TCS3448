==================================================
HITO 4 — PANEL DE SETUP DEL TCS3448 VÍA BLE WEB
==================================================

Objetivo:
Crear un panel de configuración del TCS3448 desde la interfaz Web Bluetooth.

La aplicación ya permite adquirir y visualizar datos a nivel debug.

Este hito debe permitir configurar el sensor desde la web sin recompilar firmware.

NO implementar todavía:
- gráficas espectrales avanzadas
- histogramas
- normalización RAW / ADC % / MAX=100
- transmitancia
- absorbancia
- DARK
- REFERENCE
- SAMPLE
- curvas de calibración
- auto gain
- auto exposure
- CSV
- volumetría
- algoritmos de análisis químico

Este hito se centra exclusivamente en:

1. configuración remota del TCS3448
2. validación de parámetros
3. confirmación de configuración realmente aplicada
4. mantenimiento de la adquisición BLE actual
5. documentación técnica de la arquitectura

==================================================
6. INTEGRATION TIME
==================================================

La web debe trabajar con tiempo de integración expresado en milisegundos.

Ejemplo:

Integration Time
[ 50.0 ] ms

La web NO debe conocer:

ATIME
ASTEP

La conversión debe realizarse en firmware dentro de TCS3448Manager o una capa equivalente.

Según el TCS3448:

t_int =
(ATIME + 1) *
(ASTEP + 1) *
2.78 us

La configuración activa debe devolver el tiempo REAL aplicado.

No simplemente el valor solicitado.

7. ADC FULL SCALE
==================================================

Calcular y exponer como dato READ ONLY:

ADC_full_scale =
(ATIME + 1) *
(ASTEP + 1)

limitado a:

65535

Mostrar en la web:

ADC Full Scale
[ xxxxx counts ]

Este valor no debe ser editable.

Será usado en hitos posteriores para normalización ADC %.

==================================================
12. SAMPLE PERIOD
==================================================

Añadir periodo de adquisición.

Ejemplo:

Sample Period
[ 500 ] ms

Este parámetro pertenece a la lógica de adquisición, no necesariamente al sensor físico.

Validar:

sample_period_ms > 0

y además:

sample_period_ms >= tiempo mínimo necesario para completar la adquisición

Especialmente importante en modo auto-SMUX de 18 canales.

Preferencia:
si el periodo es demasiado corto, rechazarlo y devolver un error explícito.

Ejemplo:

SAMPLE_PERIOD_TOO_SHORT

==================================================
15. APPLY_CONFIG
==================================================

La web debe tener:

[ APPLY ]

Flujo:

1. usuario modifica parámetros
2. web valida superficialmente
3. web envía configuración
4. ESP32 valida TODOS los campos
5. si todo es correcto:
   - aplica configuración
6. ESP32 devuelve ACK
7. ACK contiene configuración realmente aplicada
8. web actualiza ACTIVE CONFIGURATION

No mostrar éxito antes de recibir confirmación.

==================================================
16. CONFIGURACIÓN ATÓMICA
==================================================

gain = válido
